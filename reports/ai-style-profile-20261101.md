# AI 样式辅助：第一阶段记录

## 范围

只做“样式别名”一种受约束的操作，不生成 TeX、Lua 或任意脚本。

- 输入：DOCX 样式名称、类型（paragraph / character），不发送正文。
- AI 输出：

```json
{"version":1,"style_aliases":{"源样式名":"目标样式名"}}
```

- 应用：转换器把 `style=源样式名` 改成 `style=目标样式名`；样式定义、正文、字体、表格、图片仍由确定性转换器生成。
- 校验：源/目标必须存在，类型必须一致，未知样式、未知字段、版本不符全部拒绝。
- 失败：保留机械转换结果，不用 AI 补丁覆盖。

## 安全与隐私

- API Key 只放在当前页面内存；不写 localStorage、不写仓库、不经过本站服务器。
- GitHub Pages 是静态站，浏览器直连 API 需要服务端允许 CORS；不支持 CORS 的 endpoint 不可用。
- 只发送样式清单；不发送正文。页面明确标注这一点。

## 验证

- 手工 profile：`第1章绪论.docx` 的 `heading 1` → `heading 2`，LuaLaTeX 编译成功，23 页。
- 默认无 profile：A-Graph 输出与修复前逐字节一致，616 语料默认行为不受影响。
- 浏览器 mock API：真实页面完成转换、AI 建议、校验、应用、下载 ZIP，并在本地 LuaLaTeX 编译通过。
- 窄表、真实文档和网页既有 E2E 仍通过。

## 仍未做

- AI 只处理样式别名；表头、文本框角色、合并单元格语义尚未开放给 AI。
- 页面不内置 LuaLaTeX；生产编译仍由 Overleaf/本地完成。AI 补丁的编译验证放在测试/CI，而不是浏览器内。
- 更复杂的 AI 操作必须继续使用 JSON op 白名单和确定性渲染器，不能让 AI 直接写 TeX/Lua。
